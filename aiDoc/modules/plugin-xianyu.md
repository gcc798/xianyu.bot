# Xianyu 插件

## 职责

承载闲鱼账号、商品、消息、自动回复、RAG、订单和自动发货业务；不复制 GVA 的用户、权限、菜单和通用日志系统。

## 入口

- 后端：`server/plugin/xianyu/plugin.go`
- 协议适配：`server/plugin/xianyu/protocol/`
- 通信生命周期：`server/plugin/xianyu/runtime/`
- 前端：`web/src/plugin/xianyu/`
- API 前缀：`/xianyu`
- 菜单根路由：`/xianyu`

## 边界

- API 从 JWT 获取当前 GVA 用户，Service 使用 `owner_id` 做对象级权限检查。
- 外部闲鱼 JSON 只能由协议适配层解析，不能进入业务 Model。
- 新增或修复闲鱼接口适配前，优先查阅 [zhinianboke/xianyu-auto-reply](https://github.com/zhinianboke/xianyu-auto-reply) 中对应的登录、WebSocket、消息、商品、订单或调度实现，作为私有协议行为参考，避免盲目试错。只提取并验证协议事实，在当前 Go/GVA 分层中独立实现；不照搬其源码、架构、表结构或功能范围，并记录参考的分支/提交。其许可证为 AGPL-3.0，代码复用需另行评估。
- Cookie、Token、API Key、卡密均为敏感数据，不写普通日志或列表响应。
- 关键任务必须持久化；连接和后台任务必须支持 Context 取消。

## 当前契约

`GET /xianyu/status` 返回 `{ code, data: { plugin, database }, msg }`，用于验证插件、鉴权、Casbin 和 SQLite 接入。

账号接口位于 `/xianyu/account/*`，支持当前用户范围内的列表、创建、更新、删除、凭证写入和登录态检查。账号列表只返回 `hasCredential`，不返回 Cookie、Token 或密文；凭证使用环境变量 `XIANYU_CREDENTIAL_KEY` 提供的 Base64 32 字节密钥进行 AES-256-GCM 加密。登录态检查按账号互斥，合并官方响应的 `Set-Cookie` 后以凭证版本条件更新，避免并发陈旧结果覆盖新凭证。

二维码登录接口位于 `/xianyu/qr-login/*`，支持创建、状态轮询和取消。会话绑定当前 owner 与账号、五分钟超时，二维码由后端编码为图片；确认后只把 Cookie 加密落库并回填闲鱼用户标识，状态响应与操作日志均不返回 Cookie。遇到风控时只允许返回 `https` 的 `goofish.com` 官方验证链接，不尝试绕过验证。

商品接口位于 `/xianyu/product/*`，支持 owner 范围内的分页列表、商品业务设置与真实在售商品同步。同步使用当前账号的加密 Cookie 调用闲鱼商品列表接口，自动分页并按 `(account_id, external_product_id)` 幂等更新；只有完整同步成功后，才把远端已不存在的本地在售商品标记为下架。响应和日志均不包含 Cookie、签名或完整第三方响应。

回复规则接口位于 `/xianyu/reply-rule/*`。每个商品可配置多条模糊规则和一条兜底规则；模糊规则按优先级降序检查关键词是否为买家消息的大小写不敏感子串，首个命中即回复，未命中时使用兜底。历史精确规则按模糊规则语义兼容执行，新建界面不再提供精确匹配。当前内容为单条文本，不包含 AI、随机权重或媒体回复。

消息页面支持显式人工接管、释放和人工文本回复。人工回复使用当前真实 WebSocket 连接，并等待闲鱼服务端按 `mid` 返回 `200`；超时返回“结果未知”，不会伪装成功。发送确认后才写入出站消息记录，并自动接管该会话。关键词自动回复受商品开关和接管状态约束，同一会话的新消息会取消旧的计划任务；任务状态持久化，发送前再次检查接管和商品开关，确认发送后记录为 `keyword` 出站消息。

发货规则接口位于 `/xianyu/delivery-rule/*`，支持文本与卡片模板、卡密加密导入、库存、任务列表和明确失败重试。同一商品优先匹配指定 SKU，未命中时使用商品级规则。自动发货先通过 WebSocket 向买家发送网盘地址/卡密并等待 `mid=200`，再调用 `mtop.taobao.idle.logistic.consign.dummy` 确认平台发货；只有两步都明确成功才确认任务、更新订单并消耗卡密，网络结果未知禁止自动重试。

商品设置支持“自动续售”、延迟、续售描述和图片 URL。开启时优先从闲鱼编辑详情取完整发布快照；普通卖家无权读取该接口时，使用已同步的标题、价格、类目和原图，并保存用户可编辑的续售描述。自动发货确认后幂等创建 `xy_relist_tasks`；执行前再同步在售列表，原商品仍在售则继续等待。发布成功后把商品设置、回复规则和发货规则迁移到新商品；发布结果未知时停止自动重试。

订单页可通过卖家接口同步待发货订单；若闲鱼返回权限错误则原样转为明确业务错误，消息事件入口仍可创建订单。工作台提供账号、商品、消息、订单和发货异常统计；业务日志按 owner 隔离记录登录检查、同步、消息和发货结果。连接运行时每 30 分钟执行 Cookie 保活，异常时停止连接及任务扫描。

协议层当前支持 `/s/para` 与 `/s/sync` 外层 JSON、Base64 MessagePack 数据及内嵌内容 JSON，输出不依赖数据库的 `protocol.ChatMessage`。解析器限制消息体大小和批次数量，过滤空批次、已读回执与已识别的同步游标包；传输层会 ACK 并忽略不含同步包的控制推送。未知 LWP、坏编码和缺少 PNM ID 会返回明确错误。fixture 使用脱敏合成标识，不包含真实账号、买家、商品或订单数据。

通信 runtime 通过 `Dialer`、`Connection` 和 `Handler` 与真实传输及业务处理解耦。`Manager` 保证同一账号只有一个运行实例，每个连接使用有限消息队列，并执行可取消读取、消费和心跳；读取超时、心跳超时、队列满或处理失败都会关闭连接并进入有上限的抖动指数退避，状态接口同时返回最近一次错误。真实传输会解密当前账号 Cookie、取得并加密缓存 WebSocket Token，完成 `/reg`、`/r/SyncStatus/ackDiff`、消息 ACK 和 `/!` 心跳，只把实际同步包交给协议解析器。解析结果按 owner 和 `(account_id, pnm_id)` 唯一键幂等写入 `xy_messages`；`/xianyu/message/list` 与“消息记录”页面提供 owner 隔离的分页查询。Token 和 Cookie 均不进入 API 响应或日志。
