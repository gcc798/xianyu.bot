# 核心业务流程

## 入站消息

`WebSocket -> 协议解析 -> 内部事件校验 -> 消息唯一写入 -> 人工接管检查 -> 回复/订单分流`

- 解析失败记录协议错误并停止，不把未知字段当作成功消息。
- 唯一写入失败为重复键时视为已处理，不再次触发回复或发货。
- 队列满时记录账号级背压状态；不创建额外 goroutine 绕过上限。

## 自动回复

1. 校验 owner、账号、商品、消息方向和过期时间。
2. 若会话人工接管则记录 `skipped`。
3. 合并延迟窗口内的买家消息。
4. 按精确关键词、模糊关键词、商品兜底、AI/RAG 选择一个策略。
5. 创建唯一回复执行记录，再发送消息并记录结果。

## 自动发货

1. 订单事件幂等落库并校验远端订单状态。
2. 匹配商品/SKU 发货规则，创建唯一发货任务。
3. 短事务预占卡密等资源并提交。
4. 在事务外执行远端发送或发货 API。
5. 明确成功后核验并消费资源；明确失败可重试；超时未知进入 `verifying`。
6. 无法自动判定时进入 `manual_required`，保留完整但脱敏的事件链。

## 凭证刷新

1. 每账号互斥，检查当前凭证版本与到期时间。
2. 优先 HTTP 检查并合并 `Set-Cookie`。
3. 仅在配置允许且确有任务时启动浏览器兜底。
4. 触发人机验证时停止重试、释放浏览器并标记账号待处理。

## 二维码登录

1. 校验当前 owner 对账号的访问权，复用同账号尚未结束的二维码会话。
2. 从闲鱼官方登录页取得参数并生成二维码，API 不返回任何 Cookie。
3. 后台轮询扫码状态；确认后加密保存 Cookie，并更新账号的闲鱼用户标识。
4. 超时或取消即停止轮询；风控只提示官方 HTTPS 验证链接，不自动绕过。
