# Agent 领域

## 职责

XyAgent 是闲鱼领域内的可审计 Agent，不以某个资源来源命名，也不得把 Telegram 写死在会话、运行、工具或事件核心模型中。

## 核心记录

- `xy_agent_sessions`：owner 隔离会话；
- `xy_agent_messages`：用户与助手消息；
- `xy_agent_runs`：单次执行生命周期；
- `xy_agent_run_tools`：完整工具输入、输出、状态和耗时；
- `xy_agent_events`：追加式轨迹事件，大结果通过 call ID 引用；
- 模型、MCP Server 和 Agent 配置；
- 资源搜索、候选、任务、资源和来源记录。

## 执行生命周期

```text
消息
  -> Run
  -> 模型 Attempt
  -> 工具选择
  -> 可选审批
  -> MCP 或业务动作
  -> 追加轨迹
  -> 流式回答
```

- Run 按 owner 隔离并支持取消。
- 启用的 MCP Server 提供可用工具；尚未实现的固定能力明确返回不支持。
- 受保护动作执行前必须停在审批状态，授权后才能恢复。
- SSE 可以从已经持久化的事件 ID 续传。
- 渠道差异通过 Tool 和资源记录表达，不污染通用 Agent 模型。

## 轨迹

轨迹必须能解释执行过程且不泄密，记录：

- Turn、Step、Attempt、耗时、错误和完成状态；
- 脱敏后的系统提示词与模型请求快照；
- Tool Schema 和脱敏输入/输出引用；
- 审批和用户决策；
- 只有真实可观测时才记录 Token 指标。

API Key、Token、卡密、Cookie 和内部认证头不得进入轨迹、SSE、日志、浏览器或模型上下文。

## 资源生命周期

只保留三个稳定动作：

1. `search`：从一个或多个来源返回轻量候选。
2. `inspect`：检查元数据、来源、许可、版本、大小和可信信号。
3. `acquire`：获取确认候选、计算哈希并保存交付元数据。

来源服务持有自身凭据，浏览器和 Agent 记录只保存来源证明，不保存来源认证。

## 前端

`agent-web/` 已支持对话、Skill/Tool 手动选择、工具组、审批、时间线、事件筛选和工具检查。仍需迁移保留的模型/MCP 配置，并与完整 React 后台及闲鱼导航整合。
