# 闲鱼领域

## 职责

`server/internal/xianyu/` 负责闲鱼自动化。它不是插件，也不负责通用用户、登录、角色、字典或审计基础设施。

## 能力分组

| 分组 | 主要职责 |
| --- | --- |
| 账号 | owner 隔离账号、加密凭据、登录状态和扫码登录 |
| 连接 | WebSocket Token、注册、心跳、重连和历史补偿 |
| 商品 | 商品同步、状态和业务设置 |
| 消息 | 协议解码、幂等入库、人工接管和人工回复 |
| 回复规则 | 优先级、兜底、延迟合并和持久任务 |
| 订单 | 同步、订单事件和状态推进 |
| 发货 | 文本/库存规则、预占、任务和结果核验 |
| 续售 | 发货后续售任务、媒体上传和规则迁移 |
| 业务事件 | 脱敏的业务运行证据 |

对外闲鱼 HTTP 路径统一使用 `/xy/*`。

## 所有权和凭据

- 用户业务记录包含 `owner_id`。
- Service 在读取、修改、启动或删除对象前校验 owner。
- 凭据加密存储。
- 凭据不得进入普通响应、日志、操作记录、业务事件、Agent 事件或前端存储。
- 刷新按账号互斥，并比较版本，防止旧结果覆盖新凭据。

## 消息流程

```text
WebSocket
  -> 协议解码
  -> 事件校验
  -> 消息幂等入库
  -> 人工接管检查
  -> 回复和订单分流
```

- 重复外部消息不得再次触发回复或发货。
- 畸形消息在协议边界停止，并只记录脱敏证据。
- 队列压力必须可见，不得用无限 goroutine 绕过。

## 回复流程

1. 校验 owner、账号、商品、方向和时效。
2. 人工接管期间跳过自动回复。
3. 合并延迟窗口内的买家消息。
4. 按明确优先级和兜底选择一个策略。
5. 发送前持久化唯一任务。
6. 记录确认、失败、未知或跳过结果。

## 发货流程

1. 幂等保存订单事件并核验远端状态。
2. 匹配商品或 SKU 发货规则。
3. 每个订单只创建一个任务。
4. 在短事务中预占库存。
5. 在事务外执行远端操作。
6. 只有明确成功后才消费库存。
7. 未知结果进入核验或人工处理，不盲目重试。

## 待验收

消息和协议已经具备较多自动化及授权账号证据；真实付款、自动发货、平台确认和自动续售仍需要受控真实交易验收。
