# 枚举与字典规范

- 稳定的业务枚举统一维护在 `s_dict` 与 `s_dict_detail`。字典 `type` 标识枚举类别，条目 `value` 是业务 code，`label` 是展示 name。
- 数据库业务字段、Go 模型和 API 业务字段存储/传递 code，不存 name；Go 校验和状态流转也比较 code。
- 前端通过已鉴权的 `/sysDictionary/options` 查询启用字典项，读取 `{ code, name }`；不得再维护业务 code 到展示名称的本地映射。颜色、图标等纯展示样式可以按 code 定义。
- 字典 `code` 统一按字符串传输，数据库原字段类型不因此改变。若业务字段或控件要求数字，前端显式使用 `Number(code)` 并校验转换结果；提交时仍按 API 字段类型发送。
- 新增或修改枚举时，同一变更必须更新字典增量 SQL、Go 业务 code、API DTO/查询条件和前端字典消费者；新增字典值通过 Goose migration 写入，不回改初始化基线。
- 持久化、跨接口稳定且需要用户理解/选择或展示的枚举进入字典，包括用户可见的 Agent 轨迹事件类型。布尔开关、协议字段和临时交互状态不为了统一外观而字典化。
- 迁移历史枚举时先盘点数据库已有 code，再补缺失字典项；保留历史业务 code 不变，避免改写业务数据。
