# React 前端开发规范

## 目录职责

- `src/app/`：应用装配、全局 Provider 和启动级状态。
- `src/api/`：HTTP 方法、路径和 DTO 输入输出，不保存页面状态。
- `src/models/`：与后端合同一致的领域类型，不放组件状态类型。
- `src/pages/`：按路由组织页面；页面私有组件、Hook 和样式就近存放。
- `src/layouts/`：跨页面布局，不承载具体业务请求。
- `src/router/`：路由、懒加载和权限边界。
- `src/styles/`：跨页面共享的视觉规则；页面专属样式使用同目录 CSS Module。
- `src/utils/`：无业务状态的纯函数。业务规则不能为了复用外观而放入工具目录。

顶层按职责分层，业务页面按领域聚合。只有出现跨页面稳定复用时，组件或 Hook 才提升到公共目录。

## 文件与函数

- 页面负责查询条件、加载状态和业务动作编排；复杂弹窗、独立页面区块和具有生命周期的流程拆为同目录组件或 Hook。
- API 函数只描述协议边界，不弹提示、不跳路由、不维护组件状态。
- 函数和变量使用业务名称，例如 `cancelResourceTask`、`selectedAccount`，避免 `handleData`、`manager` 等空泛命名。
- 不创建只有参数透传作用的 Service、Repository 或通用 Hook。
- DTO 使用明确类型；禁止用 `any`、宽泛对象或新旧字段兼容分支掩盖合同不一致。

## 中文注释

- 注释说明业务规则、权限边界、时序、单位、失败恢复或不明显的技术原因。
- 不给赋值、循环、组件渲染等直观代码逐行写说明。
- 定时轮询、请求竞态、幂等键、危险操作和凭据处理必须在关键位置说明约束。
- 导出函数只有在名称和类型不足以表达合同或副作用时添加 JSDoc。

## 页面状态

- 查询页面保留加载、空、错误、筛选、重置和分页状态。
- 写操作防止重复提交，并在成功后刷新唯一数据来源。
- 删除、退出、停止连接和覆盖配置必须二次确认。
- 用户业务权限最终由后端校验；前端守卫只负责交互体验。

## 本地检查

提交前运行：

```bash
npm run check
```

`check` 依次验证格式、ESLint、TypeScript 和生产构建。重要交互还需使用真实浏览器检查。
