# Design

## Context

当前 `MCPRegistry.Discover` 在 Agent Run、工具目录、审批恢复、资源任务和 Telegram 任务中查询全部启用服务，逐个建立 Streamable HTTP 客户端、初始化并执行 `ListTools`，调用方随后关闭全部连接。`Runner` 将每个发现到的 MCP Tool 适配成 Eino Tool，因此工具数量、启动延迟和故障等待都随全部 MCP 线性增长。

现有治理层已经提供每个 Run 的工具预算、并发槽、审批、参数审计、Owner Scope 和安全结果记录；本设计保留这些边界，只替换目录发现、候选选择和 MCP 客户端生命周期。数据库结构仍只维护在 `server/internal/infra/migrations/init.sql`，不增加物理外键、CHECK、ENUM 或触发器。

## Goals / Non-Goals

**Goals:**
- 普通 Agent Run 和工具目录查询不访问全部 MCP。
- 从数据库快照快速恢复目录，后台独立刷新并保留最近成功版本。
- 健康、目录和执行连接具有明确且互不干扰的生命周期。
- 热门 MCP 通过一个共享逻辑客户端并发发出 HTTP Tool Call；活动 MCP 总数不设上限。
- 每次模型决策使用较小但可扩大的工具工作集，长任务可累计加载更多工具。
- 所有动态选择出的工具继续经过现有治理适配器。

**Non-Goals:**
- 本次不引入 embedding 模型、`pgvector` 或独立向量数据库。
- 不新增万能 MCP 调用工具来绕过具体 Tool Schema。
- 不自动重试结果不明确的写工具。
- 不改变本地闲鱼工具通过 Service 执行业务和校验 Owner 的架构。
- 不为当前只支持 Streamable HTTP 的配置同时增加 stdio 传输。

## Decisions

### 用持久目录和内存快照替代每轮发现

新增 `xy_mcp_tools` 保存最近成功发现的工具定义、Schema、annotations、检索文本、定义哈希和发现时间；`xy_mcp_servers` 增加管理员描述、标签、allow/deny、目录状态和运行策略。服务启动时先从数据库构建不可变内存快照，再异步刷新过期目录。

每个 MCP 刷新在事务中替换其目录，事务成功后重建并原子发布内存快照。单个工具无效时跳过该工具并保存安全错误；传输或目录级失败时保留整个旧快照。

备选的纯内存目录不能在重启或 MCP 离线时恢复；每轮实时发现正是当前扩展性问题，因此均不采用。

### 目录刷新使用短期发现客户端

目录刷新只负责 `Start -> Initialize -> ListTools(全部分页) -> Close`，不进入执行连接缓存。后台按 TTL 和配置变更刷新，手动刷新只影响指定 MCP；并发刷新使用固定工作槽，限制瞬时建连而不限制最终活动 MCP 数量。支持通知的活动执行客户端收到 `tools/list_changed` 时只触发刷新，不直接修改共享目录。

`mcp-go v0.41.1` 的 `ListTools` 已遍历分页，注册表接口应使用完整列表结果并为测试保留分页场景。

### 健康检查是独立短期协议探测

健康检查建立短期客户端并完成初始化与 Ping，随后关闭；它不调用 `ListTools`、不进入执行连接缓存、不刷新空闲时间，也不创建 Agent Tool 记录。定时调度使用可配置间隔、超时、有界并发和随机抖动；手动检查与同一服务的在途检查合并。

当前 SDK 使用握手生命周期并支持 Ping。未来升级到 MCP 2026-07-28 后，探测器应根据 SDK 协商能力改用 `server/discover` 或轻量协议请求；该兼容升级不改变本次对外行为。

连接或协议调用成功可以顺带更新健康状态；正常响应的工具业务错误不改变可用状态。健康检查错误先去除 URL 用户信息、认证头和值，再截断保存。

### 执行客户端按需建立并允许并发调用

MCP Tool Definition 只保存 `serverCode`、原始 Tool 定义、定义哈希和一个调用入口，不再持有发现阶段连接。实际调用时，连接目录按 `(serverCode, scopeIdentity)` 获取客户端：`shared` 使用服务编码，`owner` 使用服务编码和 Owner ID。凭据值不进入连接键或日志。

首次建连使用 per-key singleflight 语义合并并发初始化。共享 Streamable HTTP 客户端允许多个 `CallTool` 并发执行；不在外层锁住完整调用。每个连接项维护 `lastUsedAt`、`inflight`、`closing` 和代次，调用租约原子增加/减少在途计数。

默认不限制单 MCP 的并发调用；管理员可用 `maxConcurrentCalls > 0` 设置服务级信号量。它与单个 Agent Run 的 `MaxConcurrentToolCalls` 分别治理服务总并发和单 Run 并发。

备选的每次调用新建客户端浪费握手；默认多 Session 池增加状态、OAuth 和回收复杂度。只有压测证明单 Session 被服务端串行化时，才在后续变化中增加 Session Pool。

### 活动连接只按空闲 TTL 回收

不设置全局最大活动连接数。清理器周期扫描连接项，只有在空闲 TTL 到期、`inflight == 0` 且成功从连接表按代次移除后才关闭。健康检查、目录读取、目录刷新和仅被路由选中均不更新 `lastUsedAt`；真实 Tool Call 完成后更新。

服务退出时停止接受租约、取消或等待在途调用，并关闭剩余客户端。连接失效时只使当前代次失效，由一次后续建连恢复；写工具在响应未知时不自动重放。

### 两级路由先做确定性过滤，再按需使用模型

第一级 MCP Card 仅包含服务编码、管理员描述、标签和压缩的工具检索文本；第二级 Tool Card 包含 Tool Code、名称、描述、只读/审批属性和参数字段摘要，不包含完整 Schema。路由输入只使用当前消息、必要会话摘要和显式 Directive。

流程为：
1. 按 enabled、allow/deny 和主体权限过滤。
2. 显式 MCP/Tool 指令强制保留。
3. 名称、编码和标签明确匹配时直接选择。
4. 结果模糊时使用当前首选工具模型输出已知编码的结构化选择。
5. 从候选 MCP 中选择工具；低置信度或复杂任务扩大候选。
6. 只把最终候选的完整 Schema 组装成 governed Eino Tools。

默认工作集目标是 20，不是硬上限；配置保存普通目标和低置信度扩展上限。路由模型输出未知编码、解析失败或没有覆盖显式工具时回退确定性候选并扩展。路由模型调用计入本次模型预算和轨迹。

### 动态扩展复用现有模型上下文，不提供万能分发器

第一阶段在创建 Eino Agent 前完成两级路由。随后验证 Eino 是否允许在模型步骤间更新 ToolInfos；若支持，增加受控 `tool_search` 以返回经过权限过滤的 Tool Definitions。若不支持，则在模型请求边界保留消息上下文并重建带扩展工具集的 Agent。两种实现都必须把新工具包装成 `governedTool`。

不实现接受任意名称和 `map[string]any` 的 `call_any_tool`，因为它会丢失 Tool Schema、审批属性和精确参数校验。

### 审批绑定工具定义哈希

`AgentRunTool` 保存提议时的 Tool Catalog Hash。批准远程工具前从目录按 server/tool 查找当前定义，校验服务和工具仍启用、allow/deny 仍通过、哈希一致；不一致则将旧审批标记失败并要求重新提议。批准后的实际调用通过同一执行连接目录完成，不再重新发现全部 MCP。

### 管理界面区分健康和目录

MCP 设置表分别展示：健康状态、最近检查、响应耗时、目录状态、工具数量和最近刷新时间。离线但有缓存时同时显示“不可用”和“已缓存 N 个工具”，避免误导。编辑表单增加描述、标签、allow/deny、连接作用域、目录 TTL、连接 TTL 和可选并发限制；操作区提供健康检查与目录刷新。

设置页属于操作型界面，沿用现有 Ant Design 表格、Modal 和 Tag，不做无关视觉重构；重要交互需要真实浏览器验证。

### 当前不使用向量数据库

100 个 MCP、每个约 10 个 Tool 可通过两级 Card 和结构化模型选择控制上下文。只有真实任务评估显示 `Recall@K` 不足且主要原因是多语言或同义表达时，才另行增加 embedding 配置和 PostgreSQL `pgvector`；即使加入，也必须在权限过滤后与标签、关键词混合排序。

## Risks / Trade-offs

- [缓存目录可能陈旧] -> 展示刷新时间，调用前验证工具仍启用；目录变化通知或 TTL 触发刷新，定义哈希保护审批。
- [路由漏掉正确工具] -> 显式工具强制保留，低置信度扩大集合，用真实任务集测 MCP Recall@5 和 Tool Recall@20。
- [一个共享 Session 被服务端串行化] -> 先做并发压测和指标；只有证据出现时再引入多 Session 池。
- [共享 Session 携带用户状态] -> 提供 `shared`/`owner` 作用域，用户级状态必须使用 Owner 隔离连接。
- [TTL 清理关闭在途连接] -> 使用调用租约、在途计数、closing 状态和代次比较后再关闭。
- [健康检查放大外部负载] -> 有界并发、抖动、短超时和同服务检查合并；健康检查不刷新目录。
- [路由增加模型调用延迟] -> 确定性高置信度时跳过模型；记录路由 tokens/延迟并与全量工具基线比较。
- [外部描述提示注入] -> instructions 与 Tool 描述按不可信数据存储、限长，不拼入高优先级系统规则。
- [写请求断线后结果未知] -> 不自动重试，返回可核验状态并依赖业务事件确认。

## Migration Plan

1. 只在 `init.sql` 增加 MCP 配置字段、Tool Catalog 表和 Agent Tool 定义哈希；部署前说明现有环境需要按项目既有方式重建或同步初始化结构。
2. 上线目录缓存和后台刷新，先保持现有工具选择行为；验证快照恢复、分页、失败保留和管理界面。
3. 将所有 `Discover` 调用迁移到目录查询和惰性执行客户端，启用独立健康检查与 TTL 回收。
4. 启用两级静态路由并记录路由事件；用代表性任务对照全量目录评估召回、延迟和 tokens。
5. 完成 Eino 动态工具验证后启用动态扩展；验证失败则采用保留消息重建 Agent 的方案。
6. 回滚时关闭两级路由，仍从缓存目录组装全部获准工具；不得回退到每轮连接所有 MCP。目录表和新增配置字段可保留，不影响旧业务数据。

## Open Questions

- 目标 MCP 服务是否会在同一 Session 内串行处理请求，需要在实现共享客户端后用并发集成测试和真实服务压测确认；该结果只决定未来是否增加 Session Pool，不改变本次单客户端并发和 TTL 架构。
