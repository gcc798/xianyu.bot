# 项目开发与交付规范

## 1. 适用范围

本规范适用于本仓库的软件开发、工程配置、文档维护、验证和交付任务。

## 2. 工程边界

- `server/`：Go 后端。
- `agent-web/`：唯一维护的 React 前端。
- `telegram.bot/`：Telegram 资源服务。
- `docs/`：只记录当前事实，不记录源码结构、表字段或历史过程。
- 不得修改与当前需求无关的代码，也不得擅自改变公开 API、数据结构、数据库语义和原有业务行为。

## 3. 文档维护

- 架构变化更新 `docs/architecture.md`，范围变化更新 `docs/project-scope.md`。
- 产品定义更新 `docs/product.md`，设计规范更新 `docs/design.md`。
- 遵守 `LICENSE` 和 `docs/third-party-licensing.md`。

## 4. 验证

- 先运行最小相关测试，再运行受影响应用的完整检查。
- 验证失败时，应区分代码回归与环境问题，如实说明失败和未执行的项目。
- 不得把模拟测试写成真实账号或真实交易验收。

## 5. 容器验证

开发任务结束前，若环境提供 Docker 且仓库为受影响服务配置了容器，应构建或更新并启动相关容器，检查容器运行状态与服务可用性，不得重启无关服务。

若启动需要缺失凭据、外部授权或额外权限，应说明阻碍和未完成的验证。

## 6. Git 交付

开发任务完成并通过要求的验证后，自动将本任务相关改动提交并推送到当前分支。

提交前必须检查差异，只包含本任务改动，不得纳入无关或用户未授权的改动；不得强推或改写历史。验证失败、远端不明确或权限受阻时，停止提交和推送并说明原因。
